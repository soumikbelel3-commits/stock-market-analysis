# India + Global Market Analysis

A reusable Jupyter analysis project that walks **chronologically down the macro chain**,
turns the result into a sized, risk-measured long/short book, and then subjects that book
to the tests an institution would apply before allocating to it:

```
economic state → global risk → bond market → global equity → India market → company analysis
                                                                                    ↓
                    portfolio risk ← construction ← crowding ← forensics ← signal validation
                              ↓
              factor risk → execution & capacity → validation, limits & governance
```

Every notebook fetches **live data** and re-derives its conclusions on each run. Nothing
here is a static snapshot; re-run it tomorrow and the numbers, scores and levels move.

> **What this is.** These notebooks produce quantitative analysis — scores, rankings,
> ATR-derived levels, and a model portfolio with its risk measured. That is trader
> tooling, not personalised investment advice, and it is not a recommendation to buy,
> sell or short anything. The model book in notebooks 10–11 is an arithmetic exercise on
> the chain's own output, not a suggestion to trade it. You own the decisions.

## Quick start

```bash
pip install -r requirements.txt
```

Then run the notebooks **in order** — each one's output feeds the next:

```bash
cd notebooks
jupyter lab
```

Or execute the whole chain headless:

```bash
cd notebooks && for nb in 0*.ipynb 1*.ipynb; do jupyter nbconvert --to notebook --execute --inplace "$nb"; done
```

Both regression suites run offline in a few seconds and need no network:

```bash
python tests/test_guards.py && python tests/test_institutional.py
```

45 tests: 14 proving the trap guards fire, 31 proving the institutional guards fire *and*
that the new statistics agree with simulation and with known answers.

The institutional layer's deliverable is `outputs/ic_memo.md`, regenerated by notebook 14
on every run.

The notebooks ship with real embedded outputs, so you can read them without running
anything.

Each notebook's final cell appends its signal to `outputs/dashboard.json`; notebook 06
prints the first six links and notebook 14 prints all fourteen.

**Notebooks 01–06 are a research chain. 07–11 are the fund layer. 12–14 are the
institutional layer.** The fund layer answers the questions between a watchlist and a
book: does the signal work, is the accounting real, how much of each name, what can it
lose. The institutional layer answers the ones an allocator asks about the *process*: is
the Sharpe measured against cash, does the signal survive the number of tests that found
it, what is the book a bet on, can the account carry it, and can any of it be reproduced
next quarter.

Two dependencies in that second half are not obvious:

- **07 runs before everything else** in the layer. There is no point sizing a signal
  nobody has tested, and 07 also builds the machinery (`rank_ic`, `quantile_portfolios`)
  that 08 reuses.
- **09 runs before 10.** Construction needs lot sizes and F&O eligibility to build a short
  leg that can actually be traded (trap #5). This is invisible until you try to trade the
  output.

Notebook 06 is unmodified. 08 reads `outputs/nifty50_screen.csv` and writes
`outputs/nifty50_screen_filtered.csv`; filtering inside 06 would need 08's output, which
runs later — a cycle.

### The validation is allowed to say no

Notebook 07 exists to test the screen, not to justify it. On the run of **2026-09-09** its
verdict on the technical leg was **"Not proven"**: mean rank IC −0.037 at a 21-day horizon
with t = −1.62 over 107 monthly rebalances, a non-monotone quintile spread of −0.79pp, and
a long/short quintile portfolio that lost money net of a 25bps round trip. The random-score
control cleared (mean t ≈ 0.0, 0/40 trials past |t| > 2), so the harness is sound — the
signal simply is not there on this universe and period.

Six of the fifteen `TECHNICAL_SPEC` factors reached |t| > 2 with the sign **opposite** to
the one the spec assumes, clustered in short-horizon momentum and volatility (RSI14, price
vs the 20 and 50-day means). That is a coherent short-term-reversal pattern and a
hypothesis worth testing out of sample — it is explicitly **not** taken as licence to refit
the weights, because fifteen correlated tests on fifty names is exactly the selection
problem the notebook warns about.

The downstream notebooks are built anyway, and that is deliberate: the construction and
risk machinery is what lets you find this out about *any* signal, including a better one.
What the chain does not do is quietly carry on as if the screen had been validated.

## The institutional layer (12–14)

The research chain and the fund layer were built to be honest about their inputs. The
institutional layer is built to be honest about *itself* — and applying it turned up three
defects in the existing code and sharpened one conclusion the chain had already reached.

### The signal is worse than "not proven" — and the reason is quantified

Notebook 07's verdict was already **"Not proven"**. Notebook 14 recomputes the full
fifteen-factor scan and applies the corrections 07's own README asked for and did not run:

| | result |
|---|---|
| Factors naively significant at \|t\| > 2 | **6 of 15** |
| Survive Benjamini–Hochberg FDR control (α = 0.10) | **5** |
| Survive family-wise (Bonferroni) control | **0** |
| Average pairwise correlation among the factors | 0.080 |
| Effective independent tests | **7.1 of 15** |
| Family-wise 5% critical \|t\| | **2.69**, not 1.96 |
| Median largest \|t\| under the null | 1.68 |

Six of fifteen against an expected 0.75 by chance is real. **None of them clears the
family-wise bar**, and the strongest — RSI14 at t = −2.76 — barely exceeds a threshold of
2.69 that it was never measured against. The corroborating evidence points the same way:

- the block-bootstrap 95% confidence interval on the composite IC is **[−0.075, +0.004]**
  and does not exclude zero, agreeing with the Newey–West t of −1.62;
- **only 1 of 4** purged, embargoed out-of-sample folds has a positive mean IC, and the
  most recent fold is the worst (t = −3.17, hit rate 25%);
- the deflated Sharpe probability is **0.000** — the best of fifteen tries under a null of
  no skill would have reached an annualised Sharpe of 0.708, and the realised long/short
  Sharpe was −0.428.

Every significant factor carries the sign **opposite** to the one `TECHNICAL_SPEC`
assumes, clustered in short-horizon momentum and volatility. That remains a coherent
short-term-reversal hypothesis and remains explicitly **not** a licence to refit the
weights — five factors surviving FDR out of a family where none survives family-wise
control is precisely the evidence that would not replicate.

The chain's response is unchanged and now better founded: the book is built, the machinery
runs, and `report.ic_memo` prints **"DO NOT DEPLOY — paper only"** as its recommendation
line. That stance is *derived* from notebook 07's verdict rather than written, and
`report.assert_memo_honesty` fails the build if a memo ever recommends deploying a screen
that failed validation.

### Three defects the layer found
<a id="three-defects-the-layer-found"></a>

Same standard as the two bugs the fund layer surfaced: found by building on top of the
library rather than by reading it, and silently wrong rather than loud.

**1 — Every Sharpe ratio was computed against zero.** `risk.drawdown_summary` and
`backtest.curve_stats` both divided an annualised return by an annualised volatility with
no risk-free rate. At the Indian policy rate near 6.25% the overstatement is roughly
`rf / vol`, which on the current model book at 7.3% volatility is **0.83** — the reported
Sharpe was 1.18 and the excess-return Sharpe is **0.36**. Excess CAGR over cash is 2.4%.
That is the whole distance between a book that beats cash and one that does not.

`mkt.perf` recomputes everything on an excess-return basis, `perf.sharpe_correction`
prints the size of the defect deliberately, and `perf.assert_excess_return_basis` refuses
a performance block that has forgotten the rate. There is one documented exception — a
genuinely market-neutral book funded on collateral earns the rate on its cash — and it has
to be asked for (`allow_zero_rf=True`), never assumed.

**2 — `COST_BPS = 25` was flat across two different instruments.** The long leg is cash
delivery: STT at 0.10% on *both* sides. The short leg is stock futures: STT at 0.05% on
the *sell only* (0.02% until Union Budget 2026 raised it from 1 April 2026). Measured
through `mkt.costs`, the explicit round trip is **29.30bps long against 10.35bps short —
a factor of almost three.** On the current book the value-weighted all-in
figure lands at 26.5bps, so the placeholder was almost exactly right *on average* and
wrong on every individual decision it informed.

Adding square-root impact then produces the capacity answer the chain could not previously
give: at 12 rebalances a year and an assumed 300bps gross alpha, **capacity is about ₹0.5
crore.** A monthly-rebalanced concentrated book in this universe barely covers its own
costs, and that is a finding about the strategy, not about the cost model.

**3 — `panel.iloc[-1]` is a trap this project created.** `align_to_calendar` deliberately
never fills a series past its own last real observation, so the aligned panel legitimately
ends with an **all-NaN row** whenever the calendar has opened a session that has not
printed yet — most of any trading day, and all of a run made before the close.
`panel.iloc[-1]` is then a vector of NaN that looks exactly like "the latest prices", and
everything downstream inherits it in silence: a period return comes back empty, an
attribution table renders blank, nothing raises. `align.latest_row` and
`align.period_return` close it, stamping the date they actually used.

A fourth, smaller one: `portfolio.liquidity_check`, `costs.trade_cost` and
`risk.liquidity_adjusted_var` all consume an average-daily-value series and nothing in the
library computed one, so every caller rolled its own — and the obvious one-liner is wrong
twice (a partial last bar, and mean-price × mean-volume ≠ mean of the product).
`indicators.adv_value` and `indicators.daily_vol` now do it once.

### What the layer added

**Statistical validation** (`mkt.validation`). Benjamini–Hochberg and Bonferroni over the
whole factor family; the deflated Sharpe ratio, which asks what the best Sharpe would have
been under the null *given how many variants were tried*; probability of backtest
overfitting by combinatorially symmetric cross-validation; purged and embargoed splits,
because Newey–West fixes the *standard error* and does not fix a training set that contains
the test set's future; and White's Reality Check, block-bootstrapped on shared draws so
correlated candidates correctly count as fewer effective tries.

**A style factor risk model** (`mkt.factors`). Cross-sectional WLS in the Barra tradition:
exposures, factor returns, EWMA factor covariance, specific variance, and the decomposition
`w'(XFX' + D)w`. The current book is **34% systematic / 66% specific** and carries net
exposures of **+0.74 size** and **+0.64 momentum** — bets nobody wrote down. Validated
against a synthetic universe with known factor structure (recovered factor returns at
correlation > 0.85) and cross-checked against the realised return panel by
`factors.assert_model_vs_sample`.

**VaR model validation** (`mkt.risk`). The chain computed VaR four ways and cross-checked
two of them against each other, which catches a covariance mismatch and nothing else. A VaR
number is a falsifiable forecast, and now it is scored: Kupiec unconditional coverage,
Christoffersen independence — the test that matters more and that almost nobody runs, since
a model can have exactly the right *number* of exceptions and be useless if they all arrive
in one fortnight — the joint conditional-coverage test, and a Basel zone derived from
binomial quantiles rather than hardcoded. Forecasts are rolling and out-of-sample, because
backtesting a VaR computed on the full sample is trap #4 committed inside the risk system.
Also: marginal versus incremental VaR (two positions in the current book have *negative*
incremental VaR — removing them raises risk), liquidity-adjusted VaR, and the ex-ante versus
ex-post bias test real risk teams report monthly.

**Margin** (`mkt.margin`). SPAN cannot be reproduced from public data; it comes from a
proprietary daily risk array. What is computed is a scan-range approximation plus an exact
ELM, labelled `approximate` everywhere it surfaces. It shows the regulatory floor binding on
two of the five shorts, and margin rising **115% under a 3× volatility spike with no
trade** — which is the mechanism behind most forced unwinds and was previously invisible.

**A limit register** (`mkt.limits`). The chain enforced constraints in four scattered,
implicit places that were invisible until they fired. Now there is one register in
`config.RISK_LIMITS`, every limit is measured on every run whether it binds or not, and
breaches append to a dated log outside the cache. A `not measured` **hard** limit is treated
as a failure — an unmeasured hard limit is not a satisfied one.

**Reproducibility and a deliverable** (`mkt.manifest`, `mkt.report`). A run manifest
hashing environment, configuration and data — `run_id` deliberately excludes the clock, so
two runs on the same data with the same code get the same id. And an IC memo, because eleven
notebooks and a JSON dashboard are a research process, not something anyone can approve.

## Design decisions

Every data source was probed live before the architecture was fixed. Three findings shaped
the original chain; two more surfaced when the fund layer was built on top of it.

### FRED is dead — replaced with better sources

All nine FRED series tested timed out, twice. The replacements are an upgrade rather than
a compromise:

| Need | Source | Why |
|---|---|---|
| US rates | **US Treasury daily CSV** | The *entire* curve 1M–30Y, not a handful of series |
| Macro fundamentals | **World Bank API** | GDP, CPI, per-capita by country |
| India indices | **NSE `/api/allIndices`** | 139 indices with **official** PE/PB/DY and breadth |
| Prices, statements | **yfinance** | Deep history, all markets |

Yahoo's Indian sector indices were **rejected** — roughly 55% of series were missing. NSE
publishes the real thing.

### Five traps the code handles explicitly

**1 — Calendar contamination.** Downloading `BTC-USD` (7-day week) alongside equities
(5-day) in one `yf.download` forces a calendar-day index and injects ~32% spurious NaNs
into every equity series. Measured again on 2026-09-08: 31.3% on `^GSPC`, 32.4% on
`^NSEI`. All cross-market work goes through `mkt.align`, and notebook 02 demonstrates the
before/after live (19.50% → 0.00%). `align.assert_alignment()` fails the build if it
reappears.

Alignment also never forward-fills a series **past its own last real observation** — US
equities settle hours after India closes, so filling that gap would compare a stale close
to a fresh one.

**2 — `.info` is unreliable.** `returnOnEquity` is silently `None` for `RELIANCE.NS`;
`enterpriseToEbitda` is `982` for `INFY.NS`. Every ratio is therefore **computed from the
statements**, and each carries a provenance tag (`computed`, `info-fallback`,
`n/a-sector`, `unavailable`). Notebook 06 prints the distribution and asserts that no
scorecard metric arrived untracked.

A subtler case surfaced only once ratios were sanity-checked: Yahoo serves **INFY.NS
statements in USD while quoting its price in INR**, producing a PE of 1317 and PB of 447
against real values near 14 and 4.8. The `financialCurrency` field cannot be trusted to
detect it — it claims USD for `HCLTECH.NS` too, where the statements are actually INR. So
`fundamentals.resolve_scale()` decides **empirically**, testing the candidate FX rate
against the shape of the result.

**3 — Markets close at different times.** Every frame carries its own `as_of` stamp, and
the notebooks print per-series as-of tables before any cross-market comparison.

**4 — Look-ahead in the fundamental backtest.** `yfinance` serves **only current
statements**. There is no point-in-time history, so scoring 2019 means using ratios
published in 2026 — restatements included — against a Nifty 50 membership that is today's
list, not 2019's. A fundamental backtest built on that looks excellent and means nothing.

The response is asymmetric and stated rather than buried:

- The **technical leg is backtested properly**. Every input is derived from prices known on
  the scoring date, and `backtest.assert_point_in_time()` proves it on every panel.
- The **fundamental leg is not backtested at all.** Notebook 07 instead *measures* the bias:
  it scores the universe on today's fundamentals and tests that ranking against a window
  that closed before those statements existed. The IC that comes back is an artefact, and
  its size is the point.
- Therefore **any empirically-supported leg weight applies to the technical leg only.**
  `SCORE_WEIGHTS` stays a stated 50/50 prior, never a fitted result.

**5 — The shortability trap.** A market-neutral book with continuous weights is
**unimplementable in India**. Cash-market shorts cannot be held overnight; an overnight
short must be a stock future, which means only F&O-eligible names, **whole lots**, SEBI's
daily ban list, and SPAN+ELM margin on the notional rather than the net.

Measured on 2026-09-08 against NSE's live `fo_mktlots.csv`: one lot of a Nifty 50 name
costs between ₹4.3 lakh and ₹11.0 lakh, median ₹6.4 lakh. Against the default ₹1 crore
book that is **4.3%–11.0% of capital per single lot** — so the short leg cannot express any
target weight below about 4.3%, whatever the model asks for.

Sizing therefore runs **after** lot sizes are known, `portfolio.assert_implementable()`
raises when a short leg cannot be expressed in whole lots (reporting the minimum capital
that would work), and notebook 10 prints realised weights beside target weights. On the
current book the short leg's rounding error is ~420× the long leg's — longs buy in single
shares, shorts in whole lots. That ratio is trap #5 in one number.

Two rules keep the *traded* book inside the mandate. `quantize_to_lots` never rounds a
position up through the position cap — nearest-lot rounding once turned a 12% DRREDDY
target (1.68 lots) into a 14.3% short, and the monitor never saw it because it read target
weights. And `rematch_long_leg` then re-sizes the long leg, which buys in single shares, to
the short leg as traded, so net beta is neutral on the positions that will exist (+0.012
as constructed, −0.0002 as traded). The cost is gross: the current book trades at 0.82x
rather than 0.98x. Notebooks 11–14 read `realised_weight`, never `target_weight`.

### Two bugs the fund layer surfaced in the existing code

Both were found by building on top of the library rather than by reading it, and both were
silently wrong rather than loud. (The institutional layer later found three more, in
[the section above](#three-defects-the-layer-found).)

- **`fundamentals.series_for` picked the first candidate row carrying *any* data**, not the
  best-covered one. `Net Income Common Stockholders` exists for CIPLA.NS and WIPRO.NS with
  a single non-null period while `Net Income` has four, so those two names were truncated to
  one period and their earnings CAGR came back unavailable. Six such cases exist across the
  Nifty 50. Now the best-covered candidate wins, with ties keeping list order.
- **Vol targeting scaled straight through the position caps.** Caps were applied, then a
  1.7× vol-target scale multiplied every weight, turning a 12% position cap into a 21%
  position while the notebook printed "no breach" — because the assertion checked the
  pre-leverage weights. `portfolio.vol_target` now defaults to `max_leverage=1.0` (it may
  de-risk but not lever up), and the caps are asserted on the final weights.

### Library + thin notebooks

The same fetch/align/indicator logic is needed by every notebook. Putting it in `mkt/`
means a data-source fix happens in one place, and each notebook reads as analysis rather
than plumbing. The fund layer follows the same rule — five new modules, and notebooks 07–11
stay thin enough to read as argument rather than machinery — and so does the institutional
layer, with eight more behind notebooks 12–14.

That is twenty-two modules, which is worth justifying rather than assuming. The test is
whether a notebook reads as an argument: notebook 14 runs a fifteen-factor multiple-testing
correction, three VaR coverage tests, a thirteen-limit register and a generated memo in
about forty lines of code, because every one of those is a named function with its
reasoning written down where the reasoning belongs.


`quality.py` is separate from `fundamentals.py` on the `score.py` precedent: `fundamentals`
is already 500+ lines, and forensic accounting is a distinct question from ratio
computation.

The institutional modules follow the same rule. `perf` and `costs` are separate because a
cost model is an input to performance and not part of it; `validation` is separate from
`backtest` because backtesting produces a statistic and validating asks whether the
statistic survives the search that found it; `limits` and `report` are separate from
everything because governance is not analysis.

**Zero new dependencies, still.** Following the precedent that notebook 03 hand-rolled PCA
rather than adding sklearn: risk parity is a ~20-line fixed-point iteration, Ledoit–Wolf
covariance shrinkage is closed form, and constrained minimum variance uses
`scipy.optimize` SLSQP — scipy was already in `requirements.txt`. The institutional layer
holds the line: the factor model is a weighted least-squares fit in numpy, the stationary
bootstrap and CSCV are array arithmetic, and the Kupiec, Christoffersen and Basel tests
need only `scipy.stats` distributions that were already imported.

`score.py` and `dashboard.py` are small additions to the originally planned module list:
scoring spans both the fundamental and technical legs so it belongs to neither, and the
dashboard plumbing is shared by every notebook. Both exist to keep the notebooks thin,
which was the point of the library.

## Caching

The Nifty 50 fundamentals pull costs ~235 seconds cold, so everything is cached to parquet
with a per-source TTL (prices 12h, fundamentals 1 week, NSE 6h, World Bank 30 days).

- **Force fresh data:** set `REFRESH = True` in a notebook's first cell, or export
  `MKT_REFRESH=1`.
- **Cold start:** delete `data/cache/` and re-run.

A live fetch that fails falls back to cache **and says so**, reporting the age of what it
served. It never returns an empty frame dressed up as data.

## Known limitations

**FII/DII flow history.** NSE's `fiidiiTradeReact` endpoint returns **only the most recent
session**. There is no history API — `?date=` is ignored and `/api/historical/` returns
503/404, both verified. A cumulative-flow overlay therefore cannot be reconstructed
retrospectively.

Instead, every run appends the day's snapshot to `data/fii_dii_history.csv`, and notebook
05 reports how many sessions have accumulated. On a fresh clone that is one row; it
becomes a real series with use. **This file is deliberately outside `data/cache/`** —
deleting the cache is safe, deleting this loses history you cannot get back.

**No OI history either.** The same wall, in the derivatives endpoints: NSE publishes the
current option chain and nothing before it, so a crowding *percentile* cannot be computed
from one snapshot. The response is the same — notebook 09 appends each run to
`data/derivatives_history.csv`, also deliberately outside the cache. Until that
accumulates, the crowding score ranks names against each other on the day and claims
nothing more.

**Point-in-time fundamentals do not exist** in any keyless source. This is a hard ceiling
on how much of the screen can ever be validated, not a gap to engineer around — see trap #4.

**SPAN margin is approximated, not computed.** The exchange derives it from a proprietary
daily risk array — sixteen scenarios across price and volatility, plus inter-month and
short-option-minimum charges — and it cannot be reproduced from public data. `mkt.margin`
computes a scan-range proxy with the regulatory floor applied, plus an ELM leg that *is*
exact because it is a flat percentage by rule (3.5% on stock futures). Every function that
returns one labels it `approximate`. Treat it as an early warning about capital adequacy,
never as a broker's number, and never as a reason to size into the difference — the proxy
lands near 8–9% of notional, and broker-quoted initial margin on single-stock futures
commonly runs well above that. Read it as a floor.

**The short tickets are not order-ready.** The book names each short in lots but does not
check SEBI's daily F&O ban list, name a contract month, price the notional off the future
rather than spot, or model the monthly roll. Prices are the last close the run saw; re-quote
and round to tick before placing anything.

**The risk-free rate is a stated prior.** There is no keyless daily source for the Indian
91-day T-bill, so `config.RISK_FREE_ANNUAL_PCT` carries a value and an as-of date rather
than a fetch. `perf.risk_free_annual` prefers a live short rate from `dashboard.json` when
notebook 03 publishes one, and reports its provenance alongside the value either way —
every Sharpe in the project is only as good as that number, so it is never silent about
which one it used.

**Transaction-cost rates change by circular.** The statutory table in `config.COST_RATES`
is dated. STT, stamp duty, the exchange transaction charge and the SEBI fee are all revised
periodically, and brokerage is set at an institutional 2–3bps that a retail account will
not get. Re-check the table before trading against it; a stale rate is a silently wrong
cost, which is the same class of risk as the stale lot size in trap #5.

**The factor model's fundamental exposures are not point-in-time.** Momentum, low-vol and
size come from prices and are point-in-time by construction; value, quality and growth are
held at today's statement values across the estimation window, because trap #4 leaves no
alternative. For a *risk* model that is a much smaller sin than for an alpha model — a
covariance is being estimated, not an expected return, and a name's quality decile is far
more persistent than its return — but it is an assumption, and
`factors.assert_factor_pit` refuses an exposure matrix that has lost track of which styles
are which.

**One PBO figure locates the answer to about ±0.3.** Calibrated on 60 pure-noise matrices,
the probability of backtest overfitting averaged 0.507 — exactly the null — with a 5th–95th
percentile range of 0.20 to 0.83. That is enough to separate 0.1 from 0.9 and not enough to
distinguish 0.45 from 0.55. Quote it as a band.

**NSE derivatives endpoints are undocumented and change without notice.** Measured
2026-09-08: the well-known `/api/option-chain-equities` returns `{}` with HTTP 200,
`/api/quote-derivative` returns 404, and `quote-equity?section=trade_info` returns 403 —
so **delivery percentage is not obtainable**. Futures are published for only ~25
underlyings, so basis and rollover cover a fraction of the Nifty 50, and coverage is
reported rather than glossed. `derivatives.py` degrades to `stale-fallback` in the existing
style and `portfolio.py` carries a dated static lot-size table, so notebook 10 never
hard-fails when 09 is unavailable. That is what makes **notebook 09 safely cuttable**.

**Rollover is an approximation.** NSE's official figure is computed over the expiry-day
session and is not in any public JSON endpoint; what 09 reports is next-expiry OI share.

**A 50-name universe is thin** for cross-sectional statistics. Quintiles of ten, and a
rank-IC standard error near 1/√49 ≈ 0.14 — a single date's IC of 0.03 is indistinguishable
from zero. Every conclusion in notebook 07 rests on the t-statistic of the IC series across
time, with a Newey–West standard error wherever forward windows overlap.
`config.BACKTEST_UNIVERSE` is a one-line change to a wider index, and is worth widening
before trusting any per-factor result.

## Verification

The build is verified rather than asserted:

1. **All fourteen notebooks execute headless** via `jupyter nbconvert --execute`; any cell
   raising an exception fails the build.
2. **`fetch.health_check()`** must show every source returning data inside its staleness
   tolerance. Notebook 01 prints the table.
3. **Trap regression guards, in the notebooks** — `align.assert_alignment()` on every
   cross-market frame, `fundamentals.assert_provenance()` on every scorecard metric,
   `backtest.assert_point_in_time()` on every scoring panel, and
   `portfolio.assert_implementable()` on every constructed book.
4. **Proof that the guards fire** — `python tests/test_guards.py` feeds each guard a
   deliberately broken input and confirms it raises: a 7-day-calendar frame, an untracked
   provenance tag, a look-ahead panel (whole-panel and single-column), an under-capitalised
   short book, a financial that leaked past the sector gate, and a covariance matrix that
   disagrees with its return panel. It also checks that the reported minimum capital
   actually clears the guard. A guard nobody has seen fail is not a guard. 14 tests, offline,
   no network.
5. **Proof that the institutional guards fire too** — `python tests/test_institutional.py`
   does the same for the second layer: a Sharpe computed against zero, a short leg priced as
   cash equity, raw t-statistics quoted from a family scan, a VaR model falsified by its own
   backtest, exposures with no point-in-time provenance, a factor model describing a
   different book, a book the account cannot carry, a hard limit breach *and* an unmeasured
   hard limit, and a memo claiming more than its evidence. 31 tests, offline, no network.
6. **Proof that the new maths is right, not merely plausible.** Guards catch regressions;
   they do not catch a formula that was wrong from the start. So the same suite checks
   closed forms against simulation and against constructions whose answer is known in
   advance — and three real bugs were caught this way while the layer was being written:
   `expected_max_t` returned 0 for a single test where the answer is 0.674;
   `basel_traffic_light` applied the 250-day/99% thresholds at 95%, putting a well-calibrated
   model in the red zone; and `reality_check` centred its null but not its observed
   statistic, so it returned p = 0 for any family with a positive mean. Each now has a test.
   The suite also confirms the factor model recovers a *known* synthetic factor structure at
   correlation > 0.85, that PBO averages 0.5 on pure noise, that the reality check's
   false-positive rate is near nominal, and that Basel reproduces its published 4/9
   boundaries exactly.
7. **Backtest sanity** — quintile monotonicity reported; a random-score control must produce
   an IC indistinguishable from zero. If a shuffled signal scores well, the harness is
   broken.
8. **Portfolio arithmetic** — 300 randomised books confirm the caps hold, gross is
   preserved and signs survive; risk-parity contributions are equal to within 5e-8pp and
   component contributions sum exactly to total volatility; realised-vs-target tracking
